# SoundGraph — Evidencia de la API REST

**Fecha:** 21 de noviembre de 2026. **Entorno:** Docker Desktop en Mac arm64, PostgreSQL 17.12, MongoDB 8.0.38 y Neo4j 5.26.33 Community.

Se ejecutó el procedimiento de [pruebas HTTP aisladas](../api/README.md#prueba-http-aislada) y la suite de persistencia. En `soundgraph-test` pasaron **7 casos HTTP** y **6 pruebas de persistencia**. La auditoría final no encontró referencias huérfanas.

| Caso HTTP | Resultado observado |
| --- | --- |
| Disponibilidad y contrato | `/health/ready` respondió `200`; `/docs` sirvió el HTML de Swagger UI y `/openapi.json` incluyó la API y sus respuestas declaradas. |
| Sesión y controles de origen | Credenciales no válidas y sesión ausente devolvieron `401`. Una mutación de otro origen devolvió `403`; el token dejó de ser válido al cerrar sesión. |
| Descubrimiento | Para Ana se obtuvo «C.R.E.A.M.» con afinidad 1 y su ficha. El perfil nuevo devolvió vacío normal y no pudo consultar/escribir la playlist de Ana. |
| Playlists | Dos guardados simultáneos de la misma pista dieron `201` y `200` con una sola posición. Se comprobó crear, renombrar, cambiar orden, quitar y eliminar. Un orden inválido devolvió `422` y no cambió las pistas. |
| Edición editorial | Un oyente recibió `403`; el editor cambió la nota sin alterar créditos ni afinidad. Una nota inválida devolvió `422`. |
| Ficha ausente | Al retirar temporalmente una ficha la lista informó `partial: true`, la playlist conservó la pista con `song: null` y un intento de guardado se rechazó. Se restauró el documento. |
| Dependencia no disponible | Al detener el Neo4j de pruebas, la recomendación y la comprobación de salud devolvieron `503`. Al reiniciarlo, la recomendación volvió a funcionar. |

**Límite:** estas son pruebas por HTTP y contra motores reales con datos sintéticos. No prueban la maqueta de Stitch, el flujo desde una interfaz de oyente ni capacidad en producción. La duración de las suites no es una medición de rendimiento de la API.
